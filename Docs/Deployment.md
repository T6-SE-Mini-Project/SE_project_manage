# Deployment

Production topology:

```
                browser
                   |
                   |  https://<project>.vercel.app
                   v
        +-------------------------+
        |   Vercel (frontend)     |   React + TypeScript static build
        |   frontend/vercel.json  |
        +-------------------------+
                   |
                   |  /api/*  rewritten server-side (same-origin to the browser)
                   v
        +-------------------------+
        |   Render (backend)      |   Django + gunicorn in Docker
        |   render.yaml           |   WhiteNoise serves /static/
        +-------------------------+
                   |
                   |  TLS, port 22767
                   v
        +-------------------------+
        |   Aiven MySQL           |   already provisioned
        +-------------------------+
```

## Why the API is proxied instead of called directly

Authentication uses Django's **session cookie**, and every `fetch` in
`frontend/src/api.ts` sends `credentials: "same-origin"`.

If the browser called `https://bookstore-api-7g5z.onrender.com` directly, that
cookie would be a **third-party** cookie, which Safari and Firefox block by
default and Chrome restricts. Logins would appear to succeed and then every
following request would come back `401`.

`frontend/vercel.json` therefore rewrites `/api/*` to the Render service on
Vercel's side. The browser only ever sees its own origin, the session and CSRF
cookies stay first-party under `SameSite=Lax`, and no CORS layer or code change
is needed. This is why `VITE_API_BASE_URL` stays `/api` in production — see
`frontend/.env.production`.

One consequence: requests arrive at Django carrying the **Vercel** origin, so
that is the value `CSRF_TRUSTED_ORIGINS` must contain, not the Render hostname.

## 1. Backend on Render

### Deploy

1. Push this branch, then in Render: **New → Blueprint**, select the repo.
   Render reads `render.yaml` from the repository root.
2. Render prompts for every variable marked `sync: false`. Supply them from
   the Aiven console — the full list and what each one means is in
   `backend/.env.production.example`:

   | Variable | Value |
   | --- | --- |
   | `DB_NAME` | Aiven database name (e.g. `defaultdb`) |
   | `DB_USER` | Aiven user, from the service's Connection information |
   | `DB_PASSWORD` | Aiven password |
   | `DB_HOST` | `<service>.aivencloud.com` |
   | `DB_PORT` | Aiven port (e.g. `22767`) |
   | `DB_SSL_CA` | leave empty for now — see *Harden the database connection* |
   | `CSRF_TRUSTED_ORIGINS` | leave empty for now — filled in step 3 |

   `DJANGO_SECRET_KEY` is generated by Render and must not be changed later:
   rotating it invalidates every active session.
3. After the Vercel deploy (section 2), set `CSRF_TRUSTED_ORIGINS` to the
   Vercel origin, e.g. `https://online-book-store.vercel.app`. Without it
   every `POST`, including login, fails CSRF validation with `403`.

**Render may append a random suffix to the hostname** when the service name is
already taken globally — `bookstore-api` became `bookstore-api-7g5z.onrender.com`
on this deployment. The hostname is not predictable from the service name, so
after creating the service copy the exact URL from the top of its dashboard page
and make sure the rewrite destination in `frontend/vercel.json` matches it. A
mismatch makes every `/api` call from the site return Vercel's 404, with the
backend itself perfectly healthy.

`DJANGO_ALLOWED_HOSTS` needs no edit for this: `config/env.py` appends Render's
`RENDER_EXTERNAL_HOSTNAME` automatically.

The service is built from `backend/Dockerfile` rather than Render's native
Python runtime because `mysqlclient` is a C extension that needs the MySQL
client headers; the image installs them, so the build matches CI and local.

### What happens on each start

`backend/entrypoint.sh` runs `collectstatic`, then `migrate`, then binds
gunicorn to Render's injected `$PORT`. It runs at **start** and not at image
build time because Render does not pass a service's environment variables
into `docker build`, so a build-time `migrate` would have no database.

`migrate` on start is safe for the single instance the blueprint provisions.
**If you scale to more than one instance**, move it to a Render pre-deploy
command so only one process migrates at a time.

### Verify

```bash
curl -i https://bookstore-api-7g5z.onrender.com/healthz/          # 200 {"status":"ok"}
curl -i https://bookstore-api-7g5z.onrender.com/api/books/        # 200, JSON catalogue
```

`/healthz/` is Render's health check path. It deliberately does **not** touch
the database: Render restarts a service whose health check fails, and a brief
Aiven blip should not take the whole service down.

### Harden the database connection

Out of the box `DB_SSL_REQUIRED=true` encrypts the Aiven connection but does
not verify the server's certificate, which leaves it exposed to an active
man-in-the-middle. To verify it as well:

1. Download the CA certificate from the Aiven console.
2. Render → service → **Environment → Secret Files** → add it as `aiven-ca.pem`.
3. Set `DB_SSL_CA=/etc/secrets/aiven-ca.pem`.

`DB_SSL_CA` takes precedence over `DB_SSL_REQUIRED`.

### Free-plan limits worth knowing

- The instance **spins down after ~15 minutes idle**; the next request pays a
  cold start of roughly 50 seconds. The first page load after a quiet period
  will look broken but is not.
- The filesystem is **ephemeral** and the free plan has no disks, so
  `manage.py backup_data` artifacts do not survive a restart. The `BackupRun`
  audit rows live in MySQL and do persist. To satisfy OBS-NF-006 properly,
  attach a Render Disk and point `BACKUP_DIR` at its mount path, or copy
  artifacts to object storage.
- Scheduled backups need a Render cron job, which is a paid feature. A ready
  definition is commented out at the bottom of `render.yaml`.

## 2. Frontend on Vercel

1. Vercel: **Add New → Project**, select the repo.
2. Set **Root Directory** to `frontend`. This is the one setting that is not
   in the config file, and the build fails without it.
3. Framework preset, build command and output directory all come from
   `frontend/vercel.json`; leave them alone. No environment variables need to
   be set in the dashboard — `frontend/.env.production` is committed and holds
   only `VITE_API_BASE_URL=/api`, which is not a secret.
4. Deploy, then copy the assigned URL into the backend's
   `CSRF_TRUSTED_ORIGINS` (step 3 of section 1).

If the Render service is renamed, or Render assigned a suffixed hostname,
update the rewrite destination in `frontend/vercel.json` to match.

### Verify

```bash
curl -i https://<project>.vercel.app/api/books/   # 200 through the rewrite
```

Then in the browser: register, log in, add to cart, pay with the test card
`4242 4242 4242 4242`, and check the order appears under Orders. That exercises
the session cookie, the CSRF token and the proxy together.

## 3. Custom domains

Add the domain in both dashboards, then:

- Render → `DJANGO_ALLOWED_HOSTS` → add the API domain (comma-separated).
  Render's own hostname is appended automatically by `config/env.py`, so it
  never needs to be listed.
- Render → `CSRF_TRUSTED_ORIGINS` → add `https://<site-domain>`.
- `frontend/vercel.json` → point the `/api` rewrite at the API domain.

## Configuration reference

Everything is read in one place per side — `backend/config/env.py` and
`frontend/src/config.ts`. Nothing else touches the environment.

| File | Role | Committed |
| --- | --- | --- |
| `render.yaml` | Render blueprint: service, Docker build, env vars | yes |
| `backend/.env.production.example` | Reviewable copy of the production values | yes, no secrets |
| `backend/.env` | Local development values | **no** (git-ignored) |
| `frontend/vercel.json` | Vercel build + `/api` rewrite + headers | yes |
| `frontend/.env.production` | `VITE_API_BASE_URL=/api` for `vite build` | yes, no secrets |
| `frontend/.env` | Local development values | **no** (git-ignored) |

Production-only settings (all in `backend/config/settings.py`, active when
`DJANGO_DEBUG=false` and `HTTPS_ENABLED=true`):

| Setting | Effect |
| --- | --- |
| `SECURE_PROXY_SSL_HEADER` | Trusts `X-Forwarded-Proto` from Render's TLS edge |
| `SECURE_SSL_REDIRECT` | Redirects plain HTTP to HTTPS |
| `SESSION_COOKIE_SECURE`, `CSRF_COOKIE_SECURE` | Cookies only over HTTPS |
| `SECURE_HSTS_SECONDS` | One year of HSTS, subdomains included |
| `STORAGES["staticfiles"]` | WhiteNoise compressed manifest storage |

`SECURE_PROXY_SSL_HEADER` is not optional. Without it Django treats Render's
forwarded request as insecure and `SECURE_SSL_REDIRECT` sends the browser into
an **endless redirect loop**. `config/tests.py::ProductionSettingsTests` asserts
it is set, so the loop cannot be reintroduced unnoticed.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `ERR_TOO_MANY_REDIRECTS` | `SECURE_PROXY_SSL_HEADER` missing | Already set; check `HTTPS_ENABLED=true` and that you are not behind a second proxy that strips `X-Forwarded-Proto` |
| `403` with "CSRF verification failed" on login | Vercel origin not trusted | Add the exact origin, scheme included, to `CSRF_TRUSTED_ORIGINS` |
| `400 Bad Request` / `DisallowedHost` | Host not permitted | Add the domain to `DJANGO_ALLOWED_HOSTS` |
| Login succeeds, next request is `401` | Frontend is calling the API cross-origin | `VITE_API_BASE_URL` must be `/api`; the rewrite does the routing |
| `500` on any page, `Missing staticfiles manifest` | `collectstatic` did not run | It runs in `entrypoint.sh`; check the deploy log for the `==> collectstatic` line |
| `(2026, 'TLS/SSL error')` or connection refused from Aiven | TLS not configured | Set `DB_SSL_REQUIRED=true`, or `DB_SSL_CA` to the CA bundle path |
| `OperationalError: too many connections` | `DB_CONN_MAX_AGE` x workers x instances exceeds the Aiven limit | Lower `WEB_CONCURRENCY` or `DB_CONN_MAX_AGE` |
| First request after idle takes ~50s | Render free-plan cold start | Expected; upgrade the plan to avoid it |
| `(2005, "Unknown server host ... (-2)")` | The database hostname does not resolve: errno -2 is a DNS failure, so nothing reached the database. Aiven drops the DNS record when a service is powered off or deleted | Check the service is running in the Aiven console and copy the current host; verify with `nslookup <host>` before redeploying |
| A 404 shows Django's debug page, or cookies lack `Secure` | `DJANGO_DEBUG` is not `false` on the platform, so the production security block never runs | Set `DJANGO_DEBUG=false` and `HTTPS_ENABLED=true`. An empty or missing value now fails safe to `DEBUG=False` |
| Site loads but every `/api` call 404s | `frontend/vercel.json` rewrite points at the wrong Render hostname | Match it to the exact URL on the Render dashboard |
